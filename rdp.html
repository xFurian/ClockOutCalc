Remote Access

Temporary RDP
Access Portal

A public-facing access request page for temporarily allowing an authorized source IP to reach a protected remote desktop service. Access should be authenticated, logged, automatically expire, and be enforced by the firewall.

CONCEPT / INTEGRATION REQUIRED

This page is intentionally not connected to a firewall yet. The highlighted integration values below are the pieces you will replace when the backend and firewall are selected.

Request Access

The eventual user experience should be simple: authenticate, select an access duration, submit the request, and receive a temporary access result. The user's public IP should be detected server-side rather than trusted from a form field.

Backend should enforce the maximum duration regardless of what the client submits.
Store this with the audit record if you want an access history.
Do not allow visitors to manually choose an arbitrary IP address.
Recommended authentication layer
Put authentication in front of this endpoint before it can modify firewall state. A future version could use an identity provider, passkey/MFA, or another authenticated mechanism.

The public page should remain intentionally dumb. The backend performs the sensitive operations.

Recommended Firewall Model

Use one dedicated source-IP object/alias for temporary RDP access instead of dynamically creating and deleting an entire firewall rule for every request. This keeps the permanent rule simple and makes the automation layer smaller.

ComponentConceptWhat you change later
Source Dedicated temporary-access IP alias RDP_ACCESS_ALIAS
Destination Specific internal RDP server RDP_TARGET
Service TCP RDP service RDP_PORT
Automation Add source IP, wait for expiry, remove source IP Firewall adapter/backend
Authorization Authenticated user + policy check AUTH_PROVIDER
Audit User, source IP, start, expiry, result AUDIT_LOG_DESTINATION
Why an alias?
Firewall platforms such as OPNsense and pfSense support aliases for grouping host/network addresses and referencing those groups from firewall rules. OPNsense also documents API operations for adding and removing entries from aliases. citeturn0search0turn0search1

Backend Contract

Keep the frontend independent from the actual firewall vendor. Your backend should expose a small API of its own and translate that request into the firewall-specific API calls.

POST

/api/rdp/request

Authenticate the requester, determine their source IP, validate the duration, and create the temporary authorization.

GET

/api/rdp/status

Return only safe status information such as whether the current authenticated session has active access.

POST

/api/rdp/revoke

Immediately remove the requester's temporary authorization when permitted.

★ BACKEND LOGIC — ADAPT TO YOUR SERVER LANGUAGE ★

Security Requirements Before Going Live

Required

Authentication + MFA

Do not allow an anonymous internet visitor to modify firewall access.

Required

Server-Side Validation

Validate IP addresses, durations, authorization, and request state on the backend.

Required

Automatic Expiration

Never depend on the browser remaining open to revoke access.

Required

Rate Limiting

Limit repeated requests and authentication attempts from the public internet.

Required

Audit Logging

Record who requested access, what source was authorized, when it started, and when it expired.

Recommended

VPN Alternative

For long-term remote administration, consider VPN access instead of exposing RDP directly.

Do not put firewall credentials in this file.
This HTML is designed to live on a public website. API keys, firewall addresses, server addresses, RDP credentials, and privileged automation credentials belong exclusively on the protected backend.
